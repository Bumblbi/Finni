# Бэкенд «Питомец Финни»

FastAPI + SQLAlchemy 2 + Alembic + PostgreSQL. Реализует серверную часть ТЗ: игровой профиль, питомец, бюджет, покупки, цели и копилка, квесты, периоды, родительская статистика и сброс. Денежные значения — только целые игровые монеты, реальные платежи отсутствуют.

## Запуск Docker Compose

1. Установить Docker с Compose.
2. Скопировать `.env.example` в `.env`, заменить `POSTGRES_PASSWORD` на случайную длинную строку из латинских букв и цифр.
3. Выполнить `docker compose up --build -d`.
4. Открыть Swagger: http://localhost:8080/docs. OpenAPI: http://localhost:8080/openapi.json.

Compose дожидается PostgreSQL, выполняет миграции и импорт каталога отдельным одноразовым сервисом, затем запускает API с двумя Uvicorn-процессами и Nginx. Данные сохраняются в volume `postgres_data`. `docker compose down` не удаляет прогресс; `docker compose down -v` удаляет БД.

Перед публикацией в интернете необходимо настроить HTTPS на внешнем ingress/reverse proxy; включённый Nginx предназначен для локального HTTP. Токены профиля передаются только по защищённому соединению вне локальной среды. Порты БД и API наружу не публикуются.

## Локальная разработка

Python 3.12+; ниже команды для PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e '.[test]'
# Для PostgreSQL задать DATABASE_URL; без неё используется SQLite для разработки.
$env:DATABASE_URL = 'postgresql+psycopg://finni:password@localhost:5432/finni'
alembic upgrade head
python -m app.content content/catalog.json
uvicorn app.main:app --reload
```

Для SQLite убрать переменную `DATABASE_URL`. SQLite поддерживается для однопроцессной разработки и быстрых тестов, серверное развёртывание использует PostgreSQL с блокировкой строки профиля. Таблицы при старте API автоматически не создаются — сначала нужны миграции.

## API и подключение клиента

Все игровые пути начинаются с `/api/v1`. `POST /profiles` принимает игровой псевдоним, внешность питомца и флаг `demo` (по умолчанию `true`). Возвращает `access_token` и состояние. Клиент хранит токен в защищённом хранилище Android и передаёт `Authorization: Bearer <token>`. Сервер хранит SHA-256 токена. Email, телефон, дата рождения не запрашиваются; в поле игрового имени следует вводить псевдоним. Восстановление потерянного токена без персональных данных не предусмотрено.

| Метод и путь | Назначение |
| --- | --- |
| GET `/state` | Полное состояние, версия, питомец, баланс, цель и текущий период |
| GET `/catalog` | Активные товары, цели и задания; правильные ответы скрыты |
| POST `/income` | Однократный доход периода |
| PUT `/budget` | План по `required`, `wanted`, `savings` |
| POST `/purchases` | Покупка по `product_id`, `quantity` |
| POST `/savings/deposit` | Перевод `amount` в копилку |
| POST `/savings/withdraw` | Вывод `amount`, требуется `confirmed: true` |
| PUT `/goal` | Выбор `goal_id` без потери накоплений |
| POST `/quests/answer` | Ответ `quest_id`, `choice_id`, обратная связь и награда |
| PUT `/pet` | Настройки `pet`: name/body/color/accessory |
| POST `/periods/advance` | Завершение периода и расчёт роста |
| GET `/transactions` | История; `offset`, `limit` (максимум 100) |
| POST `/sync` | Атомарная обработка очереди команд |
| POST `/adult/challenge` | Арифметический пример |
| POST `/adult/unlock` | Проверка `challenge_id` и `answer`, получение adult_token |
| GET `/adult/progress` | Статистика, требуется `X-Adult-Token` |
| POST `/adult/reset` | Сброс прогресса, требуется `X-Adult-Token` и подтверждение |

Каждая игровая изменяющая команда содержит:

```json
{
  "operation_id": "682e692c-0d70-4f3b-8480-5c98d1bfa762",
  "expected_revision": 0,
  "epoch": 1
}
```

`operation_id` — новый UUID на действие, сохраняемый до отправки. `expected_revision` и `epoch` берутся из состояния. Успех возвращает `operation_id`, обучающий `feedback`, новое `state`. Повтор того же запроса с тем же UUID возвращает исходный ответ без повторного эффекта; другой запрос с тем же UUID даёт 409. Историческое состояние в повторном ответе не следует применять поверх более новой версии.

Конфликт версии — 409 `revision_conflict`; клиент должен загрузить `/state`, пересмотреть оставшиеся действия и сформировать новые команды. После сброса меняется `epoch`: старые команды отклоняются с `profile_reset`. Ошибки бизнеса имеют `detail.code` и `detail.message`; валидация Pydantic возвращает 422, отсутствие токена — 401, закрытый родительский раздел — 403.

### Offline-first

Сервер предоставляет каталог, снимок состояния и механизм воспроизведения очереди. Полная работа без сети требует реализации локальной экономики, SQLite-кеша и интерфейса на стороне мобильного клиента (в ТЗ это зона Fullstack/Frontend). Этот репозиторий не содержит Android-клиент.

`POST /sync` принимает `{"commands": [...]}` (до 100 команд). У каждой команды есть `action`: income, budget, purchase, deposit, withdraw, goal, quest, advance, customize; остальные поля совпадают с соответствующим эндпоинтом. Версии идут последовательно: 0, 1, 2 и т. д. Весь пакет коммитится только после успешной обработки всех команд. При ошибке весь пакет откатывается. Повтор пакета безопасен. Нельзя загружать произвольный итоговый баланс: сервер повторно проверяет каждое действие и текущий каталог.

Сброс — отдельная защищённая операция; он очищает серверный прогресс, сохраняет псевдоним, токен профиля и режим игры, возвращает новую эпоху и аннулирует родительский доступ. Клиент обязан удалить свою очередь и локальный кеш. Повтор сброса не сбрасывает профиль ещё раз: устаревшая версия/эпоха или аннулированный adult_token отклоняются.

## Принятые правила экономики

В ТЗ нет числовой формулы дохода, роста и срока цели. Для рабочей реализации приняты следующие правила:

- Доход — 100 монет один раз за период; его необходимо запросить явно.
- План фиксируется один раз после получения дохода. Его сумма не превышает текущий кошелёк; план не переводит деньги автоматически. Покупки сверх плановой категории допускаются при достаточном балансе, но сопровождаются пояснением и влияют на успех периода.
- Покупки повторяемы, цена и эффекты берутся с сервера. Показатели питомца ограничены 0–100. Доступно 27 комбинаций из 3 тел, 3 цветов и 3 аксессуаров.
- Задание засчитывается один раз за жизнь профиля, включая неверный ответ. Верный ответ приносит награду из каталога; неверный — объяснение без награды. Повтор после сброса разрешён.
- Период успешен, если сделана обязательная покупка, расходы обеих категорий не превысили план, чистые накопления положительны и не ниже плана сбережений. Возврат внесённых в том же периоде средств не считается регулярным накоплением.
- Рост до стадии 2 — после двух успешных периодов; до стадии 3 — после четырёх. Стадия не уменьшается. В конце периода сытость падает на 15, настроение изменяется на +5 при успехе и −5 иначе.
- Регулярность накоплений — число подряд завершённых периодов с положительным чистым пополнением.
- Прогноз цели: округлённое вверх отношение оставшейся суммы к среднему положительному чистому пополнению за все начатые периоды (нулевые периоды учитываются). При отсутствии пополнений прогноз `null`, при достижении цели — 0. Достижение цели не списывает копилку.
- Demo содержит ровно пять периодов, переключаемых без ожидания. После пятого экономика закрывается до сброса. Обычный режим разрешает переход не раньше чем через 24 часа от начала текущего периода.
- Арифметический барьер — детский интерфейсный барьер, а не проверка личности взрослого: пример действует 5 минут, до 3 попыток; разрешение действует 10 минут и связано с профилем.

## Контент без изменения кода

Редактировать JSON по образцу `content/catalog.json`. Импорт:

```sh
python -m app.content content/catalog.json
# В Docker после изменения файла (контент входит в образ):
docker compose up --build -d
```

Импорт валидирует все записи до записи в БД, выполняется одной транзакцией, обновляет записи по стабильным ID. Отсутствующие записи деактивируются, а не удаляются, чтобы сохранить историю. Менять тип существующего ID нельзя. Уже выбранная цель хранит снимок названия и суммы; её условия не меняются неожиданно при обновлении каталога. Для нового задания использовать новый ID — обновление текста не позволяет повторно получить награду. CLI доступен оператору сервера; публичного административного API нет.

## Структура данных

`profiles` — псевдоним, хеш токена, версия/эпоха; `pets` — внешность и состояние; `balances` — кошелёк и копилка с CHECK на неотрицательность; `periods` — план, фактические траты и накопления; `transactions` — журнал изменений и остатки; `content` — валидированный каталог; `goals` — снимок выбранной цели; `quest_attempts` — однократные ответы; `operations` — квитанции идемпотентности; `adult_gates` — временный родительский доступ. Связи и уникальность заданы в БД. Каждая команда и пакет sync выполняются в транзакции под блокировкой профиля PostgreSQL.

## Проверки

```sh
pytest -q
alembic check
python scripts/export_openapi.py
```

По умолчанию тесты используют отдельную временную SQLite-БД. Для проверки PostgreSQL задайте `TEST_DATABASE_URL` на **отдельную тестовую БД**: тесты создают и удаляют в ней таблицы. CI запускает тот же набор на PostgreSQL, проверяет миграции вверх/вниз и сборку Docker. Зафиксированная спецификация находится в `docs/openapi.json`.

Проверка в изолированной PostgreSQL-БД внутри Compose:

```sh
docker compose exec db createdb -U finni finni_test
docker compose -f compose.yaml -f compose.test.yaml run --build --rm tests
```

БД `finni_test` создаётся один раз. Тестовый сервис не использует рабочую БД `finni`. HTTP smoke с перезапуском API: `python scripts/smoke_http.py` (создаёт технический профиль Smoke). По умолчанию порт Compose доступен только на 127.0.0.1.
